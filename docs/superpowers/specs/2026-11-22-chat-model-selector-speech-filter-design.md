# 聊天模型下拉框过滤语音模型设计文档

## 一、功能设计

### 1.1 功能概述

聊天输入框下方的模型下拉框只列出可用于对话的模型。模型的默认类型标记承载用途语义：持有 ASR（语音识别）或 TTS（语音合成）标记的模型是语音模型，不进入对话模型下拉框。

解决的问题：

- 语音模型（如 Qwen3-ASR）出现在对话模型下拉框中，被选中后每次对话都返回 400，用户无从判断原因。
- 模型管理中「设为默认 ASR / 默认 TTS」的标记同时表达「这不是对话模型」，界面应与该语义一致。

### 1.2 能力清单

| 能力 | 说明 |
|---|---|
| 语音模型不进对话下拉 | 持有 `asr` 或 `tts` 默认类型标记的模型不出现在聊天输入框的模型下拉框中 |
| 筛选条件叠加 | 禁用模型与语音模型同样不出现；选项来自启用的、且未持有 `asr`/`tts` 标记的模型 |
| 多标记一致处理 | 一个模型即使同时持有 `chat`、`vision` 标记，只要还持有 `asr` 或 `tts` 标记，也不进入对话下拉 |
| 自动回落 | 当前选中模型因标记变更而不再属于对话模型时，选中项回落到默认对话模型或列表首项 |
| 随配置即时生效 | 模型管理中的标记变更后，聊天界面的下拉选项随之更新 |
| 范围收敛 | 仅影响聊天输入框的模型下拉，不改变模型管理、设置面板语音识别模型选项与对外模型列表 |

### 1.3 筛选规则

对话模型列表为全部模型中满足以下条件的模型，顺序沿用模型列表的原顺序（按名称升序）：

1. `enabled` 为真；
2. `default_types` 不含 `asr` 与 `tts` 中的任意一项（含其一即排除）。

`default_types` 为空、或只包含 `chat`、`vision` 的模型保留在列表中。

### 1.4 选中项维护

- 首次加载：选中默认对话模型；默认对话模型不在对话模型列表中时取列表首项；列表为空时无选中项。
- 模型列表或默认模型变化：当前选中项仍在对话模型列表中则保持；不再属于时按上一规则重新选择。
- 列表为空时输入框仍可输入；发送仍带上默认对话模型名（若存在），其能力校验由后端负责。

### 1.5 实现位置

- `web/src/stores/meta.ts` 增加派生列表 `chatModels`，由现有模型列表按 1.3 的规则计算。
- `web/src/components/chat/ChatInput.vue` 的模型选项与选中项回落逻辑改用 `chatModels`。
- 后端接口、数据结构与对外 `/v1/models` 均不变。

### 1.6 不涉及的部分

- 设置面板中语音识别模型下拉框的选项范围（仍为全部启用模型）。
- 对外 `/v1/models` 的模型列表内容。
- 后端对「指定语音模型发起对话」的处理方式（仍由上游返回 400）。
- 默认类型标记的组合规则（仍允许一个模型同时持有多种类型）。

### 1.7 验证

前端无单元测试框架，本次改动集中在 Vue 组件与 store，验证方式：

- `cd web && npm run build`：`vite build` 与 `vue-tsc` 类型检查通过。
- 人工核对：普通对话模型出现在下拉框；在模型管理中设为默认 ASR/TTS 后该模型从下拉框消失；取消标记后重新出现；当前选中模型被设为 ASR/TTS 后选中项回落到默认对话模型。
- Go 代码无改动，不新增单元测试。

## 二、迭代说明

### 2.1 与上一版差异

- 新增：`meta` store 中的派生列表 `chatModels`。
- 调整：聊天输入框模型下拉框的过滤条件由「已启用」扩展为「已启用且未持有 `asr`/`tts` 标记」。
- 调整：选中项回落逻辑除首次加载外，也处理已选模型失去对话资格的情况。
- 同步更新：`README.md` 中默认模型规则里聊天下拉框的可见性说明。
