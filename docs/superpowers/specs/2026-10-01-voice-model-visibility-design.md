# 语音识别模型与话筒可见性设计文档

## 一、功能设计

### 1.1 功能概述

Web 界面的语音输入由一项配置决定：识别模型。识别模型有值时，聊天输入框显示话筒按钮，录音经该模型转录成文字；识别模型为空时，不显示话筒按钮。

识别模型是 Web 界面自己的配置，与模型管理中的「默认语音模型」相互独立。系统首次读取语音配置时，若已存在默认语音模型，就把它的名字写入识别模型作为初值；此后识别模型只随使用者在设置面板中的选择变化，修改或取消默认语音模型都不会影响它。

解决的问题：

- 使用者只需选定一个识别模型即可开启语音输入，无需在「选模型」与「开开关」两处分别操作。
- 已配置默认语音模型的系统，语音输入开箱即用。
- 使用者可为 Web 界面单独指定识别模型，不受对外转录接口缺省模型的牵连。

### 1.2 能力清单

| 能力 | 说明 |
|---|---|
| 识别模型决定话筒可见性 | 识别模型非空时显示话筒，为空时不显示 |
| 初值取默认语音模型 | 首次读取时若存在默认语音模型，写入识别模型并固定 |
| 识别模型独立 | 初值写入后只随设置面板的选择变化 |
| 清空即关闭 | 在设置面板清空识别模型即关闭语音输入 |
| 失效模型警告 | 所选模型被禁用或删除时，话筒显示警告态并引导至设置页 |
| 自动发送 | 识别完成即发送，识别模型为空时该开关不可操作 |

### 1.3 配置项

| 键 | 类型 | 默认值 | 含义 |
|---|---|---|---|
| `voice.model` | string | `""` | Web 界面语音输入使用的识别模型，空串表示不启用语音输入 |
| `voice.auto_send` | bool | `false` | 转录完成后是否自动发送 |

`voice.model` 一行是否存在于配置表具有语义：行不存在表示「从未确定过识别模型」，可以取默认语音模型作为初值；行存在（包括值为空串）表示识别模型已确定，不再自动填充。

### 1.4 配置对象

`internal/setting` 中的语音配置：

```go
type VoiceSettings struct {
    Model    string // 识别模型，空串表示不启用语音输入
    AutoSend bool
}

// Voice 读取语音配置；modelSet 表示配置表中是否存在 voice.model 一行。
func (s *Settings) Voice(ctx) (v VoiceSettings, modelSet bool, err error)

// SetVoice 整体保存 voice.model 与 voice.auto_send。
func (s *Settings) SetVoice(ctx, VoiceSettings) error

// SetVoiceModel 只写入 voice.model，用于写入初值。
func (s *Settings) SetVoiceModel(ctx, model string) error
```

配置对象不依赖模型服务，初值的判定与写入由设置 handler 完成。

### 1.5 设置接口

| 路由 | 说明 |
|---|---|
| `GET /web/settings/voice` | 读取语音配置 |
| `PUT /web/settings/voice` | 整体保存语音配置 |

请求体与响应体：

```json
{ "model": "whisper-1", "auto_send": false }
```

#### 1.5.1 读取

1. 配置表中存在 `voice.model` 行：原样返回。
2. 不存在：查询默认语音模型。
   - 存在默认语音模型：把它的名字写入 `voice.model`，返回该名字。
   - 不存在默认语音模型：不写入，返回空串。之后再次读取时重新判定。
   - 查询出错：返回 `500`。

默认语音模型已禁用时，`Resolve` 返回 `ErrModelDisabled`；此时同样不写入，返回空串。

两个请求同时进行首次读取时，二者写入同一个模型名，结果一致，无需加锁。

#### 1.5.2 保存

- `model` 去除首尾空白后非空：必须是已存在且启用的模型，否则返回 `400 invalid_model`，消息中给出模型名。
- `model` 为空：直接保存，表示关闭语音输入。

保存会写入 `voice.model` 行，此后读取不再自动填充。

### 1.6 界面交互

#### 1.6.1 设置面板语音分组

语音分组位于「通用」分区，自上而下两项：

| 项 | 控件 | 说明文字 |
|---|---|---|
| 识别模型 | 可清空的下拉框，选项为全部启用的模型 | 用于音频转录的模型，留空则不显示语音输入 |
| 识别后自动发送 | 开关，识别模型为空时不可操作 | 开启后识别完成即发送，无需再点发送按钮 |

选择或清空识别模型、切换自动发送均立即保存。保存失败时提示错误并从服务端重新读取，界面回到真实值。

识别模型为空时自动发送开关保留原值，仅置为不可操作；重新选择识别模型后恢复可操作。

#### 1.6.2 聊天输入框

- 话筒显示条件：`voice.model` 非空，且浏览器支持录音。
- 转录请求总是通过请求头 `X-Model-Name` 携带 `voice.model`。
- 警告态条件：模型列表已加载，且 `voice.model` 不在已启用的模型中（已被禁用或删除）。警告态下点击话筒不录音，提示「所选识别模型不可用，请在设置中重新选择」。

警告态而非隐藏：隐藏会让使用者误以为语音输入消失，却无从得知原因。

### 1.7 不涉及的部分

- 对外转录接口 `/audio/transcriptions` 的模型取用顺序：表单 `model` → 请求头 `X-Model-Name` → 默认语音模型 → `400 invalid_model`。
- 默认语音模型的设置与取消规则。

### 1.8 测试

Go 单元测试：

- `internal/setting`：`Voice` 在表为空时返回默认值且 `modelSet` 为假；`voice.model` 行存在（含空串）时 `modelSet` 为真；`SetVoice` 往返；`SetVoiceModel` 只写 `voice.model`；仓库不可用、仓库出错。
- `internal/api/handler`：
  - 读取：无 `voice.model` 行且有默认语音模型时返回该模型并写入配置表，之后取消默认语音模型仍返回该模型；无默认语音模型时返回空串且不写入，之后设置默认语音模型再读取返回该模型；`voice.model` 行为空串时不自动填充；默认语音模型已禁用时返回空串且不写入。
  - 保存：`model` 非空且不存在或已禁用返回 `400 invalid_model`；`model` 为空直接保存；`model` 裁剪空白；非法 JSON。

Python 系统测试（使用者运行）：`GET/PUT /web/settings/voice` 的请求响应体只含 `model`、`auto_send`；清空 `model` 保存成功。

## 二、迭代说明

### 2.1 与上一版差异

- 移除：`voice.enabled` 配置项，以及语音设置接口中的 `enabled` 字段与设置面板中的「启用语音输入」开关。配置表中残留的 `voice.enabled` 行不再读取，不做清理。
- 调整：话筒是否显示由 `voice.enabled` 改为由 `voice.model` 是否为空决定。
- 调整：`voice.model` 的空串含义由「跟随默认语音模型」改为「不启用语音输入」；识别模型下拉框移除「跟随默认语音模型」选项，改为可清空。
- 新增：首次读取语音配置时，以默认语音模型作为 `voice.model` 的初值写入配置表。
- 新增：`Settings.SetVoiceModel`；`Settings.Voice` 增加返回 `modelSet`。
- 移除：保存语音设置时「未选模型须存在默认语音模型」的校验。
- 调整：话筒警告态由「开关已开、未选模型且无默认语音模型」改为「所选模型已禁用或删除」。
- 调整：转录请求总是携带 `X-Model-Name`。
- 调整：识别模型为空时自动发送开关不可操作。
- 同步更新：`2026-09-24-voice-input-design.md` 与 `2026-09-30-model-default-types-design.md` 中语音设置相关段落。
