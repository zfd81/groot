# 认证配置面板设计文档

## 一、功能设计

### 1.1 功能概述

设置面板提供「认证」分组，管理两项认证配置：

- **JWT 签名密钥**（`security.auth.secret`）：API Key 的签名与校验密钥，存放于配置表，集群各节点共享。
- **API Key 请求头名**（`security.auth.header_name`）：对外接口从哪个请求头读取 API Key，存放于配置表，默认 `X-API-Key`。

两项配置均由认证中间件在启动时读取一次，因此**面板上的任何改动均为重启生效**，界面须明确提示这一点。

### 1.2 能力清单

- **密钥脱敏展示**：界面只展示脱敏后的密钥（尾 4 位），并标示密钥是否已设置；明文密钥不经任何接口出服务端。
- **一键重新生成密钥**：带二次确认的「重新生成」操作，生成随机新密钥写入配置表。确认文案须说明后果：全部已签发的 API Key 立即失效，且需重启各节点才生效。
- **请求头名设置**：可自定义 API Key 请求头名，服务端校验格式；提交空值即恢复默认 `X-API-Key`。

### 1.3 接口

三个路由均挂在 Web 会话中间件之下（与其余 `/web/settings/*` 同一分组）：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/web/settings/auth` | 读取认证配置 |
| PUT  | `/web/settings/auth` | 保存请求头名 |
| POST | `/web/settings/auth/secret` | 重新生成签名密钥 |

**响应结构**（三个接口的成功响应同构，均为 `AuthSettingsPayload`）：

```json
{
  "header_name": "X-API-Key",
  "header_name_default": "X-API-Key",
  "secret_masked": "****1234",
  "secret_set": true
}
```

- **脱敏规则**：与模型 API Key、SMTP 密码共用同一脱敏函数——长度大于 8 时返回 `****` 加尾 4 位，否则返回 `****`；密钥未设置时 `secret_masked` 为空串且 `secret_set` 为 `false`。

**PUT 请求体**：

```json
{ "header_name": "X-Groot-Key" }
```

- **空串 = 恢复默认**：`header_name` 去首尾空白后为空串时，删除配置表中的对应行，回读即为默认 `X-API-Key`。
- **校验规则**：非空值须匹配 `^[A-Za-z0-9-]{1,64}$`（字母、数字与连字符，1 到 64 位），不合法返回 400（`status: invalid_request`），不写表。

**POST 重新生成**：无请求体；成功后返回与 GET 同构的响应，其中 `secret_masked` 已是新密钥的脱敏形式，明文不进入响应。

### 1.4 生效语义

认证中间件在启动时把两项配置读为快照，之后每个请求只用快照校验，不查数据库。因此：

- 面板上的改动写入配置表后，须重启服务才生效；集群部署时须重启各节点。
- 重新生成密钥后，全部已签发的 API Key 在重启后的节点上立即失效，调用方须重新获取 API Key。密钥进配置表由各节点共享，任一节点重启后签发的 API Key 在其余重启后的节点均可验证。

### 1.5 界面

- **位置**：设置面板提供「认证」分组，与「运行时」「消息发送」等分组并列。
- **重启生效提示**：不设分组级横幅，重启生效的提示体现在三处——字段说明文字、保存与重新生成的成功提示、以及重新生成的二次确认文案。
- **密钥区**：只读展示 `secret_masked`（未设置时展示「未设置」），旁置「重新生成」按钮。
- **二次确认**：点击「重新生成」弹出确认框，文案要点：①所有已签发的 API Key 将立即失效，调用方须重新获取；②需重启全部节点才生效；③操作不可撤销。确认后调 POST 接口并用响应刷新展示。
- **请求头名区**：文本输入框，展示当前值；不设独立的「恢复默认」控件，清空输入框保存即恢复默认（提交空串实现），占位文字展示默认值 `X-API-Key`，字段说明文字注明该行为。保存出错时展示服务端返回的校验消息。

## 二、迭代说明

### 2.1 与上一版差异

- 新增：三条路由 `GET/PUT /web/settings/auth` 与 `POST /web/settings/auth/secret`，及配套接口结构 `AuthSettingsPayload` / `PutAuthSettingsRequest`。
- 新增：`Settings.RegenerateAuthSecret`，无条件生成新密钥并写表（区别于幂等的 `EnsureAuthSecret`）。
- 调整：`Settings.SetAuthHeaderName` 增加空串语义（删行恢复默认）与格式校验（`^[A-Za-z0-9-]{1,64}$`，不合法返回包装 `ErrInvalidSetting` 的错误）；此前直接写入任意值。
- 此前两项认证配置无界面入口，只能直接改表；本版经设置面板的认证分组暴露（重启生效）。
